AWS released a benchmark for AI security false alarms

02
Lesson #1

Verify exploitability, not just patterns

A risky-looking API call is not enough. Check mitigations, reachability and the actual attack path.
03
Lesson #2

Measure false positives and false negatives

Accuracy alone can hide whether a tool floods you with false alarms or quietly misses real weaknesses.
04
Lesson #3

Read the deployment context

IAM boundaries, network policies and runtime controls can change whether suspicious code is actually exploitable.
05
Lesson #4

Keep human verification in high-risk reviews

AI can accelerate triage, but a model output should remain a finding to verify—not an unquestioned verdict.
06
Lesson #5

Document evidence and assumptions

Record the source, sink, mitigation and environmental assumptions so another developer can reproduce your reasoning.
