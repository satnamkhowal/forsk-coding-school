GitHub • 9 Sep 2026

A PR can now be blocked by unresolved secret alerts

GitHub added a public-preview ruleset that can prevent merging when qualifying secret-scanning alerts introduced by the pull request remain open.
02
Lesson #1

Keep credentials out of source code

Use environment variables, secret managers or platform credential stores instead of hardcoding API keys, passwords or tokens.
03
Lesson #2

Security works in layers

Push protection can stop a secret earlier. Pull-request merge protection adds another checkpoint before code enters a protected branch.
04
Lesson #3

Deleting a leaked key is not enough

If a real credential was exposed, revoke or rotate it. Treat committed secrets as potentially compromised rather than merely hidden.
05
Lesson #4

Make security checks part of merging

Tests, reviews, dependency checks and secret detection are stronger when the workflow defines which failures must block a merge.
06
Lesson #5

Know the limits of automation

GitHub says the rule supports provider, custom and generic patterns, but currently does not support AI-detected secrets.
